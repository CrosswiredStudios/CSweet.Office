# 0.9.1

Hosted Windows guests now include the existing checksum-pinned development payload (Node/npm, .NET, Python and the fixed TUN adapter). The build emits a profile declaration bound to the completed VHDX hash. Packaging verifies that hash and carries development-profile/protocol metadata into the bootstrap manifest and both support/full archives. Missing or substituted image evidence prevents packaging.

C-Sweet can distinguish ordinary-only older guests from development-capable bundles before downloading and certifying them. Destination-host restricted-runtime, builder and public-internet/dependency certification remain required before installation (SEC-INV-10). Upgrade drain and identity rules remain unchanged (SEC-INV-18).

This corrects the 0.9.0 hosted-image path, which never staged the development payload even though the Office binaries implemented protocol 1.1. The source-development image path already stages the pinned payload. Office.Contracts remains 0.10.0. Source/archive tests do not constitute hardware certification or a published release.

Local source preparation on October 14 passed real Hyper-V v15-ipv4 certification with protocol 1.1 and guest digest `sha256:d2301fccc3692f1de9945e96cf943d5b31e24b6246b3490741b8dad7f1f1f634`. Runtime isolation, brokered builds, Node/npm dependency execution, permitted public TCP/UDP, denied private/host access and lease cleanup passed; IPv6 is intentionally unavailable under this mode. All 929 assembled payload hashes were checked. This validates that local source candidate, not an unbuilt hosted archive or installation on another machine.
