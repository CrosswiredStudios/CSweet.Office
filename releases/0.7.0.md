# Office 0.7.0

Hosted development bundles for this version target **Windows x64 only**, including the Hyper-V guest image. Linux/Firecracker image publication is deferred; it no longer blocks the Windows release.

- Persist assignment cleanup state before workload execution, including creation intent, returned workload handles, and confirmed stop reports. Interrupted cleanup remains available for bounded heartbeat/reconnect recovery through `AssignmentStopJournal` and `OfficeWorker.ReplayStopsAsync`.
- Send session-bound `AssignmentStopped` evidence to Headquarters after cleanup is confirmed. Retire delivery only after accepting the matching `AssignmentStopReceipt`, retaining a tombstone against replay of the assignment and epoch.
- Record privileged destroy confirmation in RuntimeHost. A destroy failure retains unresolved state rather than reporting that the workload has stopped.

This release requires **Office.Contracts 0.8.0** and coordinated Headquarters support for assignment stop evidence and memory runtime reset. Drain the Office and wait for zero active assignments before an identity-preserving upgrade.

Recovery has explicit limits: a crash during creation before the returned handle is persisted requires operator recovery; legacy assignments without cleanup records cannot be reconstructed. The cleanup journal and privileged confirmation records remain retained. See [workload teardown and recovery](../docs/30-workloads/02-runtime-workload-lifecycle.md#12-teardown).

Hosted bundles require target-host certification and local development signing before installation. They are not production-signed or CI-certified. Live VM stop/acknowledgement acceptance remains pending; these notes do not claim that gate has passed.
