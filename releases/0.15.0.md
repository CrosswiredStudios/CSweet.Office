# Office 0.15.0

Lets an agent runtime use Git, and adds a rootless package manager to development images.

- **Git route in the guest.** The guest's local broker proxy forwards the four fixed Git smart-HTTP requests for an assigned workspace (`GET .../info/refs?service=git-upload-pack|git-receive-pack`, `POST .../git-upload-pack|git-receive-pack` under `/git/workspaces/{workspace}/{assignment revision}`) with the purpose `git.runtime`. Only an agent runtime (workload kind 1) gets that purpose; build workloads are refused. A `GET` is accepted for a ref advertisement only and carries no body. Every other path under `/git` is refused in the guest. The guest holds no Git credential: headquarters authorizes each exchange. The Office Node relays these frames unchanged.
- **git in the base Linux image.** The image build installs `git` and fails if `git --version` does not run. Agents on `CSweet.Agent.SDK` 5.20.0 or later need git 2.31 or later.
- **micromamba 2.10.0-0 in development images**, verified against its published SHA-256, with its root under the workload tools directory. It installs without root and does not change what the workload may reach on the network.
- Office.Contracts is pinned to 0.13.0 (guest protocol 1.2 body streaming and the persistent workload disk). Neither is used by this release.

This changes the guest image and invalidates the development image fingerprint. Published hosted bundles remain development bundles: the destination host must certify and development-sign the new image before installation. Drain the Office and wait for zero active assignments before an identity-preserving upgrade.

Limits: each Git exchange is buffered and limited to 16 MiB minus 64 KiB, so a larger clone or push fails until body streaming is implemented. Git LFS is not in the image.

Verification: `CSweet.Office.Tests` pass, including the new `GuestLocalBrokerProxyTests` cases. The image changes were checked for shell and JSON syntax only; this release's image build is their first run.
