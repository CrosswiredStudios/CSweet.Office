# Office 0.15.0

- The Linux development guest image includes the `sgrep` 0.3.0 semantic code search command at
  `/usr/local/bin/sgrep`, built at image construction from source revision
  `dde0c13c8d6081f9c6d6d1d33580eebf1034aecf` with a pinned Rust 1.90.0 toolchain. The Rust toolchain,
  Cargo cache and sources are removed before the image is measured.
- The image bakes the code and text embedding models and the tree-sitter parsers for C, C++, C#, Go, Java,
  JavaScript, Python, Rust, TSX and TypeScript under `/usr/lib/csweet/toolchains/sgrep`, read-only.
  `versions.json` there records the pins and `env` records the runtime settings: agents run `sgrep` with
  `HF_HUB_OFFLINE=1`, the two baked cache paths, and `SGREP_CACHE_DIR` on writable workload scratch.
  Searches need no network and download nothing at run time.
- Image construction fails unless an unprivileged offline search over a polyglot fixture succeeds from the
  read-only caches. The public-internet certification probe additionally runs `sgrep --version` and one
  offline JSON search under its existing `developmentToolchain` check; the certification suite stays
  `csweet-hardware-vm-smoke-v16`.

This release builds on 0.14.1, whose guided setup fixes it includes unchanged.

This changes the guest image and invalidates the development image fingerprint. Rebuild the guest image,
then certify and development-sign it on each destination host before installation; hosted bundles remain
development bundles. Drain the Office and wait for zero active assignments before an identity-preserving
upgrade. Workload isolation and the workload environment allow-list are unchanged (`SEC-INV-21`); the
sgrep settings are passed by the agent to its own child process. Image builds now need network access to crates.io, Hugging Face and the
tree-sitter-language-pack GitHub releases.
