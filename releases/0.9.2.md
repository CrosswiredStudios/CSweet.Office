# 0.9.2

Fix hosted Office setup failing runtime certification with `dotnet-sdk-present`. The pinned
development SDK now installs its launcher at `/usr/bin/dotnet`, the absolute path used by
`GuestProbe.DotNetSdkPresentAsync`. `/usr/local/bin/dotnet` resolves to that same launcher.
The provisioning check invokes the certification path directly, so an unrelated SDK found
through PATH cannot mask a missing launcher.

A disposable Linux container regression executes the actual SDK provisioning block on a
filesystem without either launcher, then lists the SDK through both paths as an unprivileged
user. The hosted release workflow runs this check before constructing the Windows image.
Destination-host Hyper-V certification remains required (SEC-INV-10).

Office.Contracts remains 0.10.0. This source fix requires a newly built and published 0.9.2
bundle; restarting installation with the published 0.9.1 bundle repeats the original defect.

Local validation: 225 Office tests passed with sibling Office.Contracts disabled. The Linux
regression fails with the 0.9.1 recipe and passes with this fix. The Windows binary bundle,
executable version and metadata agree on 0.9.2; prebuilt payload and hosted-manifest packaging
checks pass. The corrected hosted VHDX has not yet been built or certified on the destination.
